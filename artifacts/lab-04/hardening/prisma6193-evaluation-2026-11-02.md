### Version-matched causal source

The official [6.19.3 transaction manager](https://github.com/prisma/prisma/blob/6.19.3/packages/client-engine-runtime/src/transaction-manager/transaction-manager.ts#L229) sends COMMIT through executeRaw, then calls transaction.commit to release. If executeRaw rejects, that release call is skipped; its finally path closes/removes the wrapper. The ordinary callback then attempts rollback, but the closed transaction is no longer an active rollback target. The official [pg transaction methods](https://github.com/prisma/prisma/blob/6.19.3/packages/adapter-pg/src/pg.ts#L137) perform release in commit/rollback. This source path agrees with the actual missing release-hook/retained-checkout observation; no server-log attribution inference is needed.

The official [error conversion](https://github.com/prisma/prisma/blob/6.19.3/packages/adapter-pg/src/errors.ts#L34) retains originalCode and maps 40001 to TransactionWriteConflict; the [client engine](https://github.com/prisma/prisma/blob/6.19.3/packages/client/src/runtime/core/engines/client/ClientEngine.ts#L369) and [LocalExecutor](https://github.com/prisma/prisma/blob/6.19.3/packages/client/src/runtime/core/engines/client/LocalExecutor.ts) call the driver directly. The old Rust binder still exists in this version's source tree, but this evaluated client-engine path does not use its retained-error-ID bridge. This distinction is why merely grepping for that binder file would have been an incorrect verdict.

The component WeakRef probe intentionally uses no strong diagnostic Error/Scope array; actual transaction scopes are a separate two-entry observation structure. Version-matched [debug source](https://github.com/prisma/prisma/blob/6.19.3/packages/debug/src/index.ts) keeps the last **100 argument records** even with logging disabled. The observed current tail of 34 errors and reclamation of the earlier 1,000-error cohort are consistent with bounded debug history, but no heap-byte/GC schedule guarantee or long-running memory-safety conclusion is made. The actual earlier failed all-immediate-GC assertion remains recorded as an invalid new diagnostic assumption, not a production defect.
