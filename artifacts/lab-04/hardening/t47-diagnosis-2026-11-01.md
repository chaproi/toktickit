## 4. Minimum correction proposals and required RED evidence

### A. Implementation-ready read correction: ordinary Queue database pagination

Propose a separately authorized, narrow RED/GREEN batch in **staff-queue-service.ts** (and a small query adapter only if necessary): perform ordinary Queue owner filtering, ordering, count and page retrieval in PostgreSQL, with bounded take/skip and a coherent read-only snapshot for the related queries. Reuse existing predicates/order conventions. **Preserve owner-replacement counts.mine/unassigned** against the base scope without the selected owner predicate, while counts.matching/pagination.totalItems use the final owner-filtered scope. Do not copy Dashboard active-only formulas into ordinary Queue, remove historical owners or change safe DTOs/defaults/search/severity/null/tie ordering.

Before GREEN add a focused real API regression with more matching rows than page size and independently expected totals/order for all/unassigned/me/explicit-owner and conflicting base filters, earlier page/beyond-final behavior and ties. Observe actual Ticket retrieval is bounded by the requested page size while metadata counters remain correct. Reuse unchanged inherited Queue/query/authorization suites; do not duplicate them or replace a deterministic cardinality assertion with a flaky wall-clock threshold. This proposal needs **no contract decision or new index/pool change**. It is a concrete reduction of demonstrated unnecessary work, not a promise that T-47 will pass afterward or a fix for write conflicts.

### B. Higher-severity write correction: preserve native state at transaction completion

The minimum *behavioral* correction is at the mutation transaction completion/driver boundary: expose the actual structured SQLSTATE so the existing executor can retry **only positively confirmed 40001**, freshly, at most three attempts. The reproduction is commit-time; merely wrapping individual Action/receipt INSERT errors or adding an index does not fix native-state loss at COMMIT. **Do not add a P2034 retry, message heuristic or production log polling.**

A technical transport gate is required before choosing production files/dependencies: prove a supported driver/adapter/transaction interface can retain native commit error codes with the current Prisma callback operations. The installed Prisma 5.22 public KnownRequestError type exposes code/meta/clientVersion, and observed commit errors supply no native state. This diagnosis does not invent a working two-line adapter, unverified upgrade or direct-pg replacement for Prisma's transaction. Keep business callbacks and User-before-Ticket-before-Action gates unchanged. If no compatible path can expose native classification, report that blocker for an explicit design choice rather than silently broadening policy.

Required tests before that GREEN: two authorized independent CREATEs and two independent EDITs after coordinated real reads; fresh current tokens/keys and actual backend overlap; eventual correct responses with exactly one committed operation/history/receipt and correct parent time per command; positively observed native 40001 transported into the executor; rollback of failed attempts before fresh retries; live auth/eligibility/token rechecks each attempt. Reuse T-42 fresh-state/exhaustion helpers and retain maximum three attempts, safe 409 exhaustion, no retry for 40P01, unknown P2034, P2002/23505 or unexpected errors. Preserve defensive receipt recovery separately. If the team instead wants to retry generic P2034 (including indistinguishable deadlocks), **that would require an explicit change to the accepted retry decision/T-42 boundary**, not authority supplied by this batch. No such decision is made here.

**Concrete next corrective batch:** ordinary Queue bounded retrieval is ready for a narrow test-first implementation; the write fix first needs the structured-commit-error transport proof/design gate above. Both remain blockers to accepting the original workload, and a Queue improvement alone cannot declare GREEN. The other three read routes need further layer-specific evidence before tuning. No full workload rerun is proposed until a separately authorized correction and its relevant checks justify one.
